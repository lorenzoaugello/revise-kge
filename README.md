# REVISE: Knowledge Update and Removal in Continual Knowledge Graph Embeddings
This repository contains the code and data behind the paper *REVISE: Knowledge Update and Removal in Continual Knowledge Graph Embeddings*

The repository contains the implementation, experiment drivers, cached raw run records, and analysis utilities for **REVISE**. This is a continual knowledge graph embedding (KGE) update method for streams containing additions, deletions, and supplied replacement pairs.

This works aims to face the issue of continual knowledge update for KGE methods: we consider, all at once, addition, removal and substitution, which are generally treated in isolation in relevant previous Continual KGE literature.

In this readme file, we provide a summary of the methodology implemented in the paper adn described in its Section 5.

## Methodology

At update step $t$, the graph change is represented as additions $A_t$, deletions $D_t$, and substitution pairs $S_t=((h,r,o),(h,r,o'))$. REVISE combines five signals: (1) positive KGE training on added and replacement triples using self-adversarial negative sampling; (2) a calibrated hinge penalty that lowers scores of deleted and superseded triples toward relation-specific plausibility thresholds estimated from held-out validation triples; (3) a relation-functionality-weighted pairwise margin that ranks a supplied replacement above the old triple; (4) replay and score distillation on retained triples; and (5) proximal embedding anchors and locality constraints that limit update drift. New entities use relation-role prototype initialization. The update uses a fixed optimization budget and a shared scorer interface for TransE, RotatE-L2, and ComplEx.

Experiments use four established datasets for knowledge graph completion and link prediction: 
- FB15k-237, 
- WN18RR, 
- CoDEx-S,
- CoDEx-M.
  
The primary stream contains three update steps, each mixing additions, removals, and substitutions. The streams are constructed synthetically from each dataset's training split. Evaluation uses filtered head and tail ranking over the entity universe present at the relevant step. We compare against different baseline methods, namely: 
- Stale, 
- FT-Add (blind), 
- FT-Snapshot, 
- Tombstone-neg, 
- NegGrad+,  
- Retraining Oracle.
  
We consider the following evaluation metrics, described in Section 6 of the paper. So, we include results for link-prediction quality (MRR and Hits@10) on test, added, removed, cumulatively removed, and retained triples; substitution accuracy; Forgetting Efficacy; Oracle Deviation (OD); and update-time speed-up.

### Main results reported in the paper

In the main text of the paper (Section 7.1, Tables 2-5), the reported main results are averaged across TransE, RotatE, and ComplEx. We report the full results for each model and each dataset in the Appendix. In summary, REVISE's removed-fact MRR is close to the retraining oracle on CoDEx-M (0.185 vs. 0.192), CoDEx-S (0.196 vs. 0.231), and FB15k-237 (0.296 vs. 0.289); WN18RR shows a larger gap (0.350 vs. 0.249). Its cumulative removed-fact MRR is within 0.047–0.061 of the oracle across all four datasets. Substitution accuracy is 0.881, 0.986, 0.712, and 0.953 on CoDEx-M, CoDEx-S, FB15k-237, and WN18RR, respectively. Across 60 paired main-config comparisons, REVISE has lower OD than NegGrad+ in all cases, Tombstone-neg in 91.67%, and FT-Add (blind) in 71.67%; its win rate over FT-Snapshot is 53.33%. REVISE and FT-Snapshot share the best reported average OD rank (1.83). Reported update speed-ups range from 7.2x to 45.1x over retraining, depending on the dataset. Test and added-fact performance remain below the retraining oracle, so the gains are concentrated in removal behavior and replacement ordering.

The results for the ablation studies are reported and described in Section 7.2, Table 6.

The CSV records are available in this repository to inspect the main-run results without rerunning training. `data/results_snapshot/README.md` describes their coverage. Scenario-specific and sensitivity results can be also generated by the supplied drivers.

```bash
 python -m pip install --upgrade pip

```

If your CUDA setup requires a particular PyTorch wheel, install the matching PyTorch build from the official PyTorch installation selector before `pip install -e .`.

## Data

Download the benchmark train/valid/test splits and cache them locally:

```bash
python scripts/download_data.py
```

The downloader uses the public source URLs declared in `src/revise_kge/engine.py`; files are stored under `data/raw/` and excluded from version control. We do not redistribute here the benchmark data. We recommend consulting the upstream repositories and dataset terms before downloading or redistributing them. Use `REVISE_DATA_DIR=/path/to/cache` to choose another cache directory.

Synthetic update streams are generated at run time from training triples. Their random seeds, event proportions, stream length, and entity universe are configured in the shared experiment implementation. Substitution pairs are generated synthetically and supplied to the method; importantly, the method does not retrieve or verify real-world corrections.

## Reproduce the experiments

The default `paper` preset matches the following reported protocol for KGE hyperparameters: embedding dimension 200; Adam base training with learning rate $10^{-3}$, batch size 1,024, 64 negatives, self-adversarial temperature 1, and cosine annealing; base training epochs 150 (FB15k-237), 200 (WN18RR and CoDEx-S), and 100 (CoDEx-M). Continual updates use 600 Adam steps at learning rate $5\times10^{-4}$ with batches of 512 and 64 negatives. Seeds are 0–4 for the main and ablation experiments; auxiliary scenario/sensitivity experiments use seeds 0–2. Contraction quantile selection uses a separate tuning stream with seed 1000 and validation-only selection.

Run all experiment groups in sequence:

```bash
python scripts/run_all.py
```

Or run one task at a time:

```bash
python scripts/run_tuning.py
python scripts/run_main.py
python scripts/run_scenarios.py
python scripts/run_ablations.py
python scripts/run_sensitivity.py
```

Each run writes per-run CSVs and base checkpoints under `results/`. Completed CSV runs are skipped on restart, so interrupted jobs can resume. Set `REVISE_RESULTS_DIR=/path/to/results` to use persistent or larger storage. Set `REVISE_PRESET=smoke` to run the reduced pipeline configuration for a quick execution-path check; Be aware that smoke results may not be comparable to the paper's full results.

The main full-preset run performs 60 dataset/model/seed configurations, each with three update steps and retraining-oracle runs. The full scenario, ablation, and sensitivity grids add substantial computation, for which a CUDA GPU is recommended. Outputs are stochastic training results; hardware and library versions can produce small numeric differences.

## Summarize or inspect results

Aggregate the archived main and ablation CSVs:

```bash
python scripts/summarize_results.py \
  --input-dir data/results_snapshot \
  --output-dir results/summary
```

After running experiments, use `--input-dir results` to summarize newly generated records. The script writes derived per-run metrics, mean/std result summaries, paired OD comparisons with Holm-adjusted p-values, and average OD ranks.

## Limitations

The following is a summary of the main limitations of our work, as stated in Section 9 of the paper: 

The update streams are generated from static benchmark KGs rather than
collected from real-world change logs, and substitutions are supplied to
the method and are limited to object replacements. The entity universe is
kept fixed, so the experiments do not cover removing entities from the
candidate set. We evaluate three embedding models and do not establish
that the method transfers to every KGE architecture. Finally, reducing
the score of a deleted fact is a behavioral update objective; our
experiments do not establish a formal machine-unlearning guarantee.
